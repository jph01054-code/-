# 스마트스토어 자동 클릭 — Windows v2

ON/OFF, 판매 링크, 제품 상태, 옵션 검색·체크, 티켓팅 시작 시간, 포인트·카드·결제 설정을 한 화면에 모았습니다. 이전 버전은 `smartstore-windows`, 이 버전은 `smartstore-v2` 브랜치입니다.

현재 UI는 검은색이며, 상태·로그를 포함한 모든 글꼴을 기존 대비 25% 확대했습니다(화면 픽셀 단위 반올림). 프로그램은 화면 오른쪽 절반, Google Chrome은 왼쪽 절반으로 배치하고 세로는 작업 표시줄을 제외한 전체 작업 영역을 사용합니다. 좁은 창에서는 설정 카드가 한 열로 정렬되며 중앙 영역을 스크롤할 수 있습니다.

## 설치·실행

1. Windows 10/11에 Python 3.11 이상을 설치합니다. Python Launcher와 Tcl/Tk를 포함하세요.
   **Google Chrome도 설치되어 있어야 합니다.** 개인 크롬 창과 별도의 전용 프로필을 사용하며 기존 개인 창을 조작하지 않습니다. Chromium을 따로 설치하거나 대신 실행하지 않습니다.
2. GitHub에서 `smartstore-v2` 브랜치를 선택하고 **Code → Download ZIP**을 누릅니다.
3. ZIP 전체를 압축 해제한 뒤 `install.bat` → `start.bat` 순서로 실행합니다.
4. 먼저 **연습 모드**에서 동작을 확인하세요. 실제 결제나 외부 상품 요청은 없습니다.

처음 `start.bat`을 실행할 때 실행 환경이 없으면 설치를 자동으로 시작합니다. 설치 중 검은 창이 뜨는 것은 정상이며, 설치 완료 후 프로그램 창을 엽니다. 설치에는 인터넷 연결이 필요합니다.

### 검은 창만 뜨는 경우

- **Run install.bat first.**: 이전 실행 파일을 사용 중이며 실행 환경이 없습니다. 같은 폴더의 `install.bat`을 먼저 실행하고, 완료 후 `start.bat`을 실행하세요.
- **Python 관련 오류**: Python 3.11 이상 설치 시 Tcl/Tk, Python Launcher와 Add Python to PATH를 포함하세요.
- **설치 실패**: 검은 창의 마지막 오류 문구를 확인하세요. 설치 성공 메시지가 나오기 전에는 설치가 완료된 것이 아닙니다.
- **프로그램 시작 실패**: 새 버전은 오류 안내 창을 띄우고 `%LOCALAPPDATA%\SmartStoreAssistantV2\startup-error.log`에 원인을 저장합니다.
- **Can't find a usable init.tcl**: Python의 화면 구성용 Tcl 데이터 파일을 찾지 못한 상태입니다. 최신 버전은 현재 Python에 함께 설치된 Tcl/Tk 경로를 확인하고, 파일이 존재할 때 해당 프로세스에서만 경로를 연결합니다. 파일이 없거나 오류가 계속되면 Python 설치 프로그램의 Modify에서 **tcl/tk and IDLE**을 추가하세요. 이미 선택되어 있다면 설치 프로그램의 **Repair**를 실행하세요. 임의의 Tcl 파일을 다운로드하거나 다른 Python 버전의 파일을 복사하지 마세요.

ZIP 안에서 바로 실행하지 말고 전체 압축을 해제한 폴더에서 실행하세요. `diagnose.bat`으로 브라우저나 구매를 시작하지 않고 GUI 생성 여부만 확인할 수 있습니다.

설치 과정에서도 실제 GUI 생성 검사를 먼저 실행합니다. Windows에서 앱 화면 생성까지 성공한 경우에만 의존성 설치를 계속합니다.

이 배포본은 Python 소스이며 EXE는 포함하지 않습니다.

## 화면 설정

| 항목 | 동작 |
|---|---|
| 프로그램 ON/OFF | ON이면 브라우저를 열고 예약 시각에 자동 진행합니다. OFF는 종료를 요청합니다. |
| 판매 링크 | 스마트스토어·브랜드스토어 HTTPS 상품 링크 |
| 제품 상태 | 구매가능 / 일시 품절 / 확인 필요 |
| 제품 옵션 개수 | 실제로 읽은 색상·사이즈 등의 옵션 그룹 수를 표시하고, 필요한 입력란을 활성화합니다. |
| 제품 옵션 | 각 그룹에 ‘블랙’, ‘XL’처럼 포함 문구를 입력합니다. 여러 그룹을 순서대로 선택합니다. |
| 제품 옵션(필수) | 그룹별로 하나만 체크합니다. 하나만 일치하면 자동 선택하고, 여러 개면 선택을 기다립니다. 실행 중 검색 문구를 바꾼 뒤에는 **옵션 적용** 또는 Enter를 눌러 반영합니다. |
| 제품 옵션 없음 | 체크하면 옵션 입력란을 비활성화하고 옵션 선택을 건너뜁니다. 실제 옵션이 감지되면 진행하지 않습니다. |
| 제품 수량 | 1~99개 |
| 티켓팅 시작 시간 | 년·월·일 / AM·PM / 시·분·초를 각각 입력합니다. 한국시간이며 **입력 시각 자체가 감시 시작 시각**입니다. 10시 오픈에 09:59부터 감시하려면 AM 09시 59분 00초를 입력하세요. 12 AM은 자정, 12 PM은 정오입니다. |
| 구매하기 | 체크하면 옵션·수량 선택 후 주문 화면으로 진행합니다. 해제하면 구매 버튼 감지 알림만 합니다. |
| Npay 포인트 | 사용 안함 / 금액 지정 / 전액사용 |
| 다른 결제수단 | 현대카드 / 신한카드 / 농협카드 / 국민카드 / 네이버페이머니카드 |
| 최대 결제금액 | 배송비 포함 한도. 확인할 수 없거나 초과하면 자동 결제를 중단합니다. |
| 결제하기 자동 클릭 | 체크했을 때만 검증 후 결제 버튼 클릭을 시도합니다. 기본값은 해제입니다. |
| 결제 비밀번호 | 가려서 입력합니다. 이번 실행 메모리에만 전달하고 파일·로그에는 저장하지 않습니다. 비워 두면 인증은 직접 진행합니다. |

카드·배송은 실제 주문 화면에서 해당 항목을 식별하고 선택 결과를 확인할 수 있어야 자동 진행합니다. 배송 방법은 택배입니다. 저장된 설정을 읽어도 실행 모드는 항상 연습으로 시작합니다.

## 사용 순서

판매 링크·옵션·수량·시작 시간과 결제 설정을 입력하세요. 실제 상품 모드에서는 ‘크롬 열기 · 로그인 확인’으로 전용 크롬에 직접 로그인하고 지정 상품 화면으로 돌아오세요. 이후 ON을 켜면 감시가 시작됩니다. 브라우저가 열린 동안 기본 설정 입력창은 잠기지만 옵션 그룹의 검색 문구와 선택은 수정할 수 있습니다. 입력 중인 문구가 즉시 구매에 사용되지 않도록 **옵션 적용/Enter** 또는 명시적인 체크로 반영합니다.

예를 들어 옵션 그룹이 2개면 옵션 1에 ‘블랙’, 옵션 2에 ‘XL’을 설정합니다. 첫 그룹을 선택해야 다음 그룹이 활성화되는 상품도 순서대로 처리합니다. 그룹 수나 선택 결과를 확실히 확인할 수 없으면 선택을 기다리거나 수동 확인으로 중단합니다. 감지되지 않았다는 이유만으로 옵션 없는 상품이라고 자동 판단하지는 않습니다.

자동 진행 순서:

```text
시작 시각 대기 → 새로고침 → 재입고 확인 → 옵션 검색·선택
→ 수량 확인 → 구매하기 (한 번만)
→ 주문 상품·옵션·수량 확인
→ 포인트·카드·택배 설정 및 결과 재확인
→ 총액·한도·결제 버튼 금액 일치 확인
→ 결제하기 (자동 클릭 체크 시, 한 번만)
→ 지원되는 일반 비밀번호 입력 / 그 외 직접 인증
```

F8은 ON/시작, F9는 일시정지/재개, F10은 OFF/중지입니다. Windows 전역 핫키가 충돌하면 화면 ON/OFF를 사용하세요. 진행 중인 요청·클릭은 취소되지 않을 수 있습니다. 프로그램 종료가 이미 생성된 주문이나 결제를 취소하지는 않습니다. 다시 실행하기 전 주문 내역을 확인하세요.

새로고침 간격은 **0.1~5초만 허용**하며 기본값은 2초입니다. 이전 응답 및 화면 확인이 끝난 뒤 적용하는 간격이고 요청은 겹치지 않습니다. 따라서 설정을 0.1초로 해도 서버 응답 시간을 포함한 전체 주기가 0.1초라는 뜻은 아닙니다. 오류 시 대기 간격은 최대 5초까지 늘리며, 접근 제한(401/403/429) 또는 연속 오류 5회 발생 시 멈춥니다. 최대 감시 시간은 기본 20분이며 일시정지 중에도 연장되지 않습니다.

## 연습 모드와 실제 화면의 차이

연습 모드는 시작 시간과 무관하게 ON 후 바로 진행합니다. 화면에 **연습 모드 · 실제 주문/결제 없음**을 표시하고 외부 요청을 차단합니다. 두 번의 새로고침 후 입고되는 상품과 연습용 포인트·카드·인증 화면이 있습니다. 연습 비밀번호는 테스트용 숫자를 입력하세요. 실제 비밀번호를 사용할 필요가 없습니다.

**실제 네이버 주문·결제와 Windows GUI/전역 핫키는 이 환경에서 검증하지 못했습니다.** 로컬 연습 화면 통과가 실제 사이트 동작을 보장하지는 않습니다.

Linux 가상 화면에서 실제 Tk 창 생성·검은색 테마·글자 확대·반 화면 배치·스크롤과 옵션 입력란 활성화를 검증했습니다. Windows 환경 및 모니터 배율에 따른 최종 배치는 추가 확인이 필요합니다.

현재 실제 화면 어댑터는 다음을 확실히 식별할 수 있을 때만 진행합니다.

- 접근성 이름이 구매하기/바로구매/Npay 구매하기인 버튼·링크, 네이티브 select 또는 연결된 팝업/combobox의 옵션 그룹, 수량 입력란
- 네이버페이 HTTPS 주문 화면의 단일 상품 링크와 그 상품 행에 표시된 옵션·수량
- 명확하게 표시된 포인트 입력·전액사용 체크, 선택 카드·택배 라디오 버튼
- 단일 ‘총 결제 금액’과 같은 금액이 표시된 ‘○○원 결제하기’ 버튼

일치 항목이 없거나 여러 개이거나 한도 초과면 결제를 시도하지 않고 수동 확인을 기다립니다. 실제 화면에서 다른 구조를 사용하면 지원되지 않습니다. 인증·CAPTCHA·접근 제한을 우회하지 않습니다.

구매 버튼 상태는 화면에 인식됨/비활성/미인식/중복 확인 필요로 표시합니다. 보이는 활성 버튼만 사용하고, 팝업 뒤의 버튼은 누르지 않습니다. 버튼이 화면 밖에 있으면 해당 위치로 스크롤합니다. 이 보완 역시 실제 네이버 화면의 구매 성공을 검증했다는 뜻은 아닙니다.

비밀번호 자동 입력은 확인된 네이버페이 HTTPS 도메인의 **일반 password 입력란**과 명확한 확인 버튼에 한정합니다. 랜덤 보안 키패드, 팝업, 외부 카드사 인증, 추가 인증은 직접 진행해야 합니다. 버튼 클릭 또는 비밀번호 입력 시도는 결제 성공을 뜻하지 않습니다. 성공 여부와 결제 금액은 주문 내역에서 확인하세요.

자동화는 금액 변경을 감지하면 멈추지만, 브라우저를 유지하므로 사용자가 직접 하는 결제를 막지는 않습니다.

## 저장 위치

`%LOCALAPPDATA%\SmartStoreAssistantV2`에 설정과 전용 브라우저 프로필을 저장합니다. 연습과 실제 로그인 프로필은 분리되어 있습니다. 비밀번호와 카드 번호를 설정에 저장하지 않습니다. 브라우저 프로필에는 로그인 세션이 포함될 수 있으므로 이 폴더를 공유하거나 GitHub에 올리지 마세요.

설정 파일 손상 시 기존 파일을 자동으로 덮어쓰지 않고 기본값과 안내를 표시합니다. 기본 상품은 이전에 요청한 스킨푸드 제품이며 링크·수량·옵션·한도는 변경할 수 있습니다.

## 검증

설치 후 프로젝트 폴더에서:

```bat
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

테스트는 한국시간 예약, 설정 저장, 비밀번호 저장 제외, 취소·오류 재시도 제한과 로컬 연습 화면의 옵션 부분 검색, 주문 진입, 포인트·카드·택배 설정, 한도 검사, 결제 버튼·일반 인증 흐름을 검사합니다. 실제 사이트 결제 테스트는 포함하지 않습니다.
